# Стандартизированная работа — И-ГЦ-02

Рабочая расчётная версия бланков **МУ-41-2024 «Стандартизированная работа», редакция №4** для обработки листовых салатов, овощей и зелени на SOLIA. Данные инструкции отделены от демонстрационных предположений.

## Готовые файлы

- **[Excel: 28 связанных листов](deliverables/Стандартизированная_работа_И-ГЦ-02.xlsx)** — основной файл, без макросов и внешних формульных связей.
- **[Памятка по заполнению, PDF](deliverables/Памятка_по_заполнению.pdf)** — где менять данные, как устроены расчёты и ограничения модели.
- **[Проекты СОП, Word](deliverables/Проекты_СОП_И-ГЦ-02.docx)** — статические примеры для томата, латука и периодической санобработки. Word **не обновляется автоматически** при изменении Excel. Для других продуктов и актуальных чисел печатайте СОП из Excel.

> **ДЕМО / ПРОЕКТ, не утверждённые нормативы.** Объёмы, выходы, ручные длительности, планировка и целевые улучшения — явно обозначенный пример. Факты внедрения, обучение, подписи и положительные результаты аудита не вымышлены.

## Как подставить свои показатели

1. Открыть XLSX в Microsoft Excel или LibreOffice Calc с автоматическим вычислением. Для Excel при необходимости: **Ctrl+Alt+F9**. Предпросмотр файла не обязан выполнять пересчёт.
2. Начать с **«Начало»** — это оглавление с переходами и сводкой.
3. Изменять **жёлтые** ячейки. **Синие** — формулы, **серые** — требования/справочник источника.
4. Проверить **«Контроль»** после изменений. Пустой результат означает отсутствие/непригодность данных, а не нулевое значение.
5. Перед внедрением провести реальные наблюдения, проверить технологию и ОТ, согласовать, утвердить СОП и обучить сотрудников.

| Лист / адрес | Что вводить |
|---|---|
| `Ввод!B6:B15` | Реквизиты, дату, составителя, продукт для подробных форм, основания данных ДО/ЦЕЛЬ |
| `Ввод!B17:B23` | Длительность **одной смены**, перерывы, фиксированную подготовку/завершение, ресурсы |
| `Ввод!B25:B26` | Счётчик помывок к началу смены и резерв завершения неполного блока |
| `Ассортимент!F8:J25` | План годного после мойки в кг, выход подготовки, выход мойки, плановую партию и массу партии при замерах |
| `Замеры ДО`, `Замеры ЦЕЛЬ` | Жёлтые `E:N` в каждом из 18 блоков: флаги учёта, причины, **длительности отдельных элементов в секундах**, не накопительные отсечки |
| `Периодическая работа` | Жёлтые санитарные длительности; частоту и время подачи чистой тары |
| `Карта СР!C8:F13` | Координаты реального маршрута, м. Время переходов надо измерять отдельно |
| `Общий список улучшений`, `Отчет об улучшении` | Проблемы, мероприятия, статусы и **фактические** результаты после контрольных наблюдений |
| `Показатели!B:C` | Самостоятельные отчётные данные выпуска, запасов, наработки и качества; это **не** автоматически сменный заказ |
| Чек-листы и лист ознакомления | Реальные результаты проверки, доказательства, обучение, даты и подписи |

Формулы защищены от случайного изменения **без пароля**: «Рецензирование → Снять защиту листа». Новые продукты, операции, санитарные переходы между видами, оборудование и параллельная работа требуют расширения модели, а не вставки произвольных строк в фиксированные диапазоны.

Компоновка адаптирована под расчёты и многономенклатурный процесс — это **не графическая копия** ФЦК. Исходные шаблоны сохранены без изменения в `sources/`. Примеры приложений №4–6 использованы как примеры, а не как источник времён для овощей. Посторонние скрытые листы общепроектного аудита/справочника контактов из приложения №7 не включены в рабочую книгу; они остаются в исходном файле.

## Расчётная логика

- **Единица процесса — партия / одна загрузка SOLIA**, а не кг. Выход подготовки и выход мойки разделены: `в мойку = план годного / выход мойки`; `сырьё = в мойку / выход подготовки`; число партий округляется вверх по каждому виду.
- Масса партии ограничена таблицей И-ГЦ-02. При изменении массы замера относительно плановой партии появляется предупреждение. Время не масштабируется по кг; последняя неполная партия консервативно получает полный цикл.
- Такт = доступный фонд одной смены / сумма партий. Количество сотрудников **не умножает такт**.
- Флаг 0 или хотя бы один пропущенный/ошибочный элемент исключает **целый цикл**. Минимумы, максимумы, среднее, размахи и регулировочные секунды пересчитываются по полным учтённым циклам.
- Регулировка выполняется по МУ, стр. 17, только на необходимые ручные элементы, не на переходы, ожидания и потери. Проверяется `Σ t отрег = T min`.
- Средневзвешенные значения II типа рассчитываются **по числу партий** каждого вида.
- Периодическая работа: минимум трёх наблюдений / периодичность для анализа. Сменный план использует **целые события**, включая резерв завершения неполного блока. Эта работа не вычитается повторно из фонда смены.
- Автоматическая программа и одновременное ожидание оператора не складываются дважды в длительности процесса.
- Способность оборудования: загрузка + программа + выгрузка + санитарные остановки. Монопродуктовые мощности разных видов **не суммируются**. Сменная выполнимость всего процесса включает также подготовку, переходы и подачу тары.

### Границы модели

Базовая схема — **1 SOLIA + 1 оператор, последовательно, без перекрытия ручной работы с мойкой**. При другом количестве ресурсов пересчитываются агрегированные нижние оценки загрузки и появляется предупреждение; новый график, размещение целых партий и отдельные санитарные счётчики автоматически не строятся.

Режимы SOLIA: **01 — 450 с; 02 — 180 с; 03 — 300 с**. После каждой четвёртой помывки: слив → после слива выключение и обесточивание → промывка моющими средствами и дезинфекция. Эти требования не сокращаются в прогнозе.

И-ГЦ-02 **не задаёт** санитарное средство, концентрацию, температуру, экспозицию, точные СИЗ и длительности ручных действий. Демонстрационные **480 с не являются назначенной дезинфекционной выдержкой**. Эти параметры необходимо проверить по утверждённым документам, инструкциям средств и паспорту SOLIA.

## Воспроизводимая сборка и проверка

Для **использования XLSX** Python не нужен. Команды ниже нужны только для пересборки пакета:

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/build_workbook.py
.venv/bin/python scripts/verify_release.py
.venv/bin/python scripts/build_documents.py
```

Для генерации PDF нужны шрифты DejaVu Sans в `/usr/share/fonts/truetype/dejavu/` (пакет `fonts-dejavu-core`).

- `data/process.json` — транскрипция технологических данных и явно обозначенные исходные предположения.
- `scripts/process_model.py` — независимая эталонная арифметика.
- `scripts/build_workbook.py`, `scripts/workbook_reports.py` — построение связанных листов, форм, диаграмм, подсказок и защиты.
- `scripts/recalculate.py` — проверка формул и заполнение начальных кэшей формул/диаграмм для предпросмотра. После правок в Excel пересчёт выполняет сам Excel.
- `tests/test_workbook.py` — **17 тестов**: исходный пример, изменение спроса/выходов/смены, исключение целых циклов, нулевые и некорректные данные, точность мощности, санитарные события, выбор продукта, отсутствие вымышленного аудита и ресурсные ограничения.
- `data/verification.json` — результаты проверки и SHA-256 исходников/книги.
- `data/input_cells.json` — полный реестр редактируемых ячеек с пояснениями.

Проверка выполнена программным движком `formulas` и независимой арифметической моделью; это не ручное тестирование в GUI Microsoft Excel/LibreOffice. Готовая книга использует обычные функции Excel, без динамических массивов, VBA и внешних формульных связей. Word содержит только статический снимок.
